# EMAH — Component Conformance Model

## Status

**EMAH-ARCH-15-P01 / CANDIDATE**

---

# 1. Governing Distinctions

**Component Defined != Component Implemented**

**Component Implemented != Component Conforms**

**Component Conforms != Runtime Enforcement**

**Runtime Enforcement != Proof Obligation Discharged**

---

# 2. Candidate Conformance Dimensions

A later component conformance review may evaluate:

- interface fidelity;
- state-model fidelity;
- gate fidelity;
- authority-boundary fidelity;
- effect-model fidelity;
- recovery-model fidelity;
- evidence-model fidelity;
- obligation-model fidelity;
- failure-mode fidelity;
- lineage fidelity.

---

# 3. Conformance Scope

Conformance must be bounded to:

- component version;
- dependency version;
- implementation version;
- runtime profile;
- configuration;
- declared interfaces.

Therefore:

**Component Conformance Within Scope != Global System Conformance**

---

# 4. Proof Boundary

Conformance evidence may support proof work.

It does not independently discharge proof obligations.

Therefore:

**Conformance Evidence != Proof Discharge**
